# ADR-020: DBバックアップ

## ステータス
決定（非機能要件「バックアップ機能必須」「バックアップ時の帯域制御」、ADR-010 の具体化）

## 決定
- 対象は中央DB（MariaDB）。`mariadb-dump`/`mysqldump`をコマンドテンプレート（capability `db-backup`）で実行し、`--single-transaction`で稼働中でも一貫したダンプを取る。
- ダンプの出力を**アプリ側で速度制限しながら**gzip圧縮して保存する（`Backup:RateLimitKBps`、既定10MB/秒、0で無制限）。読み出しを絞るとパイプ越しにダンプコマンドも待たされるため、DBサーバーとの転送量も絞られる。復元時も同じ上限で流し込む。
- DBの認証情報は権限600の一時オプションファイル（`--defaults-extra-file`）で渡し、コマンドライン引数（`ps`で見える）には出さない。
- 保存先はこのノードの`Backup:Directory`（既定`/var/lib/systemagent/backups`、0700）。NFS等をマウントして指定してもよい。保持数（`Backup:Retention`、既定7）を超えた古いものから削除する。
- 定時実行は`Backup:DailyAt`（HH:mm）。中央DBは共通のため、定時実行はクラスタ内の1台だけで設定する。
- 失敗・中断時は作成途中のファイル（`.partial`）を残さない。
- 復元（DBの全置き換え）は、誤操作防止のためファイル名の再入力を必須とする。ダウンロード・復元・削除は監査ログに残す。
- ダンプツールが無いノードでは501（このノードでは利用できません）。他ノード経由で、ツールのあるノードのバックアップを操作できる（ADR-018の転送）。

## 検証
AlmaLinux 9（MariaDB 10.5）で作成 → ユーザー追加 → 復元で元に戻ることを確認。Ubuntuノードから他ノード経由で一覧・ダウンロードできることを確認。
