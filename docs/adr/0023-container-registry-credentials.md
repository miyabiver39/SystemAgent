# ADR-023: コンテナレジストリの認証情報

## ステータス
決定（基本設計書 7章 コンテナ管理の補完）

## 決定
- 非公開レジストリの認証情報（レジストリ・ユーザー名・パスワード/アクセストークン）を**ノードごと**に登録する。パスワードはローカルの暗号化シークレット（`container.registries`）に保存し、APIは返さない。
- 登録時に実際にログインし、**成功した場合だけ保存**する（誤った認証情報を残さない）。編集時にパスワードを省略すると保存済みの値を使う。
- **イメージ取得（pull）の直前に毎回ログインし直す**。Podman（root）の認証ファイルは `/run/containers/0/auth.json`（tmpfs）で再起動により消えるため、ランタイムのログイン状態には依存しない。未登録のレジストリは匿名で取得する。
- ログインはテンプレートのコマンド `registryLogin`（`login --username {username} --password-stdin {registry}`）で行い、**パスワードは標準入力で渡す**（プロセス一覧やログに出さない）。`registryLogout` は削除時に実行し、失敗しても（ログイン状態が既に無い等）登録は削除する。どちらも任意コマンドで、未定義のテンプレートでは 501。
- レジストリ名は `ホスト名[:ポート]`（小文字に正規化、`index.docker.io` 等は `docker.io` にそろえる）。イメージ参照のレジストリ判定は podman/docker と同じ（先頭要素に `.` か `:` を含むか `localhost` ならレジストリ、それ以外は Docker Hub）。
- ログイン・削除は監査ログに残す（パスワードは含めない）。

## 範囲外
- HTTPのみのレジストリや自己署名証明書の許可（`registries.conf` / `daemon.json` の編集）は行わない。OS側で設定する。
- 全ノードへの一括登録は行わない（各ノードで登録する。デプロイ機能で必要になったら検討する）。
