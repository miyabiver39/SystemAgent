# ADR-025: 監査ログの閲覧

## ステータス
決定（[ADR-009](0009-audit-log-scope.md) で「将来対応」としていた閲覧UIを追加する）

## 決定
- 記録（中央DBのみ）の方針は ADR-009 のまま。記録に**実行したノード名**（`Cluster:NodeName`）を追加した。中央DBに全ノードの記録が集まるため、どのノードで行われた操作か区別できるようにする。追加前の記録はノード名なし。
  - 他ノードへの転送（ADR-018）で行った操作は、実行者が `ユーザー名@転送元ノード`、ノードが実行したノードになる。
- 閲覧は WebUI の「監査ログ」画面と `systemagent audit list|export`。条件は期間・実行者・操作（前方一致。`deploy` で `deploy.*`）・ノード・内容の部分一致。新しい順にページ単位（最大500件）で返す。
- CSV出力（UTF-8 BOM付き、最大10万件）。表計算ソフトで式として解釈されないよう、`= + - @` 等で始まる値の先頭に `'` を付ける。**CSV出力自体も監査ログに残す**（`audit.export`、条件を記録）。
- 閲覧はログインしていれば誰でも可（ロールは設けない。QA-0003）。中央DB停止中は閲覧できない（503）。DB停止中の操作は各ノードのアプリログにのみ残る。
- 検索用に `OccurredAt`・`Action` にインデックスを追加（`Action` は varchar(64)、実行者は varchar(256) に変更）。
- DBの記録に失敗した後は30秒間DB記録を試みない（ADR-009の実装）が、マイグレーション適用後はすぐに再開する（バージョンアップ直後、列追加前に失敗した場合への対策）。

## 範囲外
- 監査ログの保持期間・自動削除、改ざん防止（ハッシュチェーン等）、外部（syslog/SIEM）への転送。必要になれば別途検討する。
