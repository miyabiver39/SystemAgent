# ADR-026: イメージのPushとレジストリ内のイメージ管理（ZOT）

## ステータス
決定（依頼: コンテナイメージのPush、レジストリはZOT、認証は htpasswd の Basic / Digest）

## 決定
- **Push**: ノード上のイメージを、登録済みのレジストリ（ADR-023）へ送る。
  - 送り先はレジストリを含む名前（`zot.example.com:5000/app/web:1.0`）で指定し、未登録のレジストリには送らない（認証情報なしで送って失敗させない）。
  - 送り先の名前を一時的に付けて（`tag`）送り（`push`）、元から無かった名前なら送信後に外す（ローカルのイメージ一覧に送り先の名前を残さない）。名前の無いイメージをIDで指定した場合は、外すとイメージ自体が消えるため付けた名前を残す。
  - 送る直前に登録済みの認証情報でログインし直す（pullと同じ。Podmanのログイン状態は再起動で消える）。
- **レジストリの証明書**: レジストリごとに「証明書を検証しない」を設定できる（自己署名証明書・HTTPのZOT向け）。Podmanでは login / pull / push に `--tls-verify=false` を付ける。Dockerはコマンドで切り替えられないため、OS側の `daemon.json`（insecure-registries）で設定する。
- **レジストリ内のイメージ管理**: OCI Distribution API で、リポジトリ一覧（`/v2/_catalog`）・タグ一覧（`/v2/<repo>/tags/list`）・タグ削除（`DELETE /v2/<repo>/manifests/<tag>`）を行う。一覧は Link ヘッダをたどって全件取得する。
  - 要求はノード（サーバー）から送る。ブラウザからレジストリへは直接接続しない（レジストリがノードのネットワークにしかない構成に対応するため。他ノードのレジストリ操作はノード転送で行う）。
  - 認証はサーバーの要求（`WWW-Authenticate`）に応じて **Basic / Digest** を使い分ける（.NET の資格情報処理）。ZOT の htpasswd は Basic。
  - 証明書を検証しない設定のレジストリは、HTTPSで接続できなければHTTPで接続する（podman の `--tls-verify=false` と同じ扱い）。検証する設定ではHTTPに切り替えない。
  - タグ削除はタグ指定で行い、同じ内容を指す他のタグは残る（ZOTで確認）。タグ指定の削除に対応していないレジストリではエラーにし、ダイジェスト指定での削除（他のタグも消える）は自動では行わない。容量の解放はレジストリのガベージコレクションに任せる。
- Push・タグ削除は監査ログに残す（`image.push`、`registry.tag.delete`）。

## 検証
- 単体テスト: login / pull / tag / push のコマンド生成（TLS検証の有無、Podman/Docker）、レジストリAPI（ページング、タグ削除、エラーの変換、HTTPへの切り替え条件、リポジトリ名の検証）。
- WSL上のZOT v2.1.21（自己署名TLS、htpasswd）で、登録（誤パスワードは保存しない）→ node-a / node-b（転送）からのPush → リポジトリ・タグ一覧 → node-b でのpull → タグ削除（他のタグは残る）をCLI・WebUIで確認した。
