## Q1. 提案: WSL2を検証環境として利用する

**案の概要**
- Windows上でWSL2（Windows Subsystem for Linux 2）を有効化し、以下のディストリビューションを導入する。
  - RHEL系検証用: Rocky Linux 9（RHEL9互換）
  - Debian/Ubuntu系検証用: Ubuntu 24.04
  - 両ディストリビューションともsystemdを有効化（WSL2は`/etc/wsl.conf`の`systemd=true`設定でsystemd起動に対応済み）し、Podman/Docker等をインストールする。
- **利点**: 私（Claude Code）はBashツールから`wsl -d <ディストリビューション名> -- <コマンド>`という形で直接ディストリビューション内のコマンドを実行できるため、Capability Provider実装（systemctl操作、ネットワーク設定、NTP設定、Podman操作等）を人手を介さず自動検証できます。VMコンソールを都度開いてもらう必要がありません。
- **制約**:
  - Keepalived + VIPによるノード間フェイルオーバーの検証には、WSL2ディストリビューション同士がネットワーク的に到達可能である必要があります（WSL2はデフォルトでNAT配下のため、複数ディストリビューション間・Windowsホストとの疎通設定が別途必要になる場合があります）。まずは単一ノードでの機能検証から始め、マルチノード検証は必要になった時点で追加のネットワーク設定（ミラーモード等）を検討します。
  - EOL版OS（例: CentOS 7等）はWSL2用の正式イメージが提供されていない場合があり、対応できないものがあります。
  - 実機のNIC切替やKeepalived VIP切替など、一部の検証はWSL2では再現が難しく、最終的な実機（VM含む）での確認が別途必要です。

**確認したいこと**
- 上記の方針（WSL2 + Rocky Linux 9 + Ubuntu 24.04、Claude Codeが`wsl`コマンド経由で直接操作）で進めてよいですか？
- WSL2の有効化（Windows機能の有効化が必要な場合あり）、ディストリビューションのインストールを実行してよいですか？
- 他に候補となる仮想化基盤（Hyper-V VM等）を優先したい希望はありますか？（Hyper-VはVMごとに固定IPを割り当てやすくKeepalived検証がしやすい一方、Claude CodeからはSSH経由の操作になり、VM作成自体は手動または別途自動化が必要です）
