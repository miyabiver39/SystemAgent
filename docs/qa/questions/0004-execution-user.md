# 0004: SystemAgentの実行ユーザーとコンテナの実行形態

- ステータス: 未回答
- 起票日: 2026-09-26
- 関連: 基本設計書 5.2節（「専用実行ユーザー所有」）、ADR-013 ②コンテナ管理

コンテナ管理（Podman/Docker）の実装に着手しました。今後のネットワーク設定・NTP設定・Keepalived管理も含め、OSコマンドを**どの権限で実行するか**を決める必要があります。**暫定方針で実装を進めています**。

## Q1. SystemAgentサービスの実行ユーザー
- **暫定方針（実装中）: rootで実行する（systemdサービス）**
  - コンテナ・ネットワーク・NTP・Keepalived・サービス管理はいずれもroot権限が必要なため、最も単純で確実。
  - 秘密情報ファイル（master.key等）はroot所有・600とする。
- 代替案: 専用ユーザー（例: `systemagent`）で実行し、必要なコマンドだけsudoers（NOPASSWD）で許可する。
  - 設計書5.2節の「専用実行ユーザー所有」に近く、侵害時の影響を限定できる。
  - 反面、許可コマンドの列挙・維持が必要で、OS/バージョンごとに差が出る。
  - 実装上はコマンド実行時に`sudo -n`を付けるだけで切り替えられるよう、設定項目（`CommandExecution:UseSudo`）を用意しておきます。

## Q2. 管理対象コンテナはrootfulか
Podmanでは、rootで起動したコンテナ（rootful）と一般ユーザーで起動したコンテナ（rootless）は別々に管理され、互いに見えません。
- **暫定方針: rootfulコンテナ（`sudo podman ps`で見えるもの）を管理対象とする。**
- 既存の自社ソフトウェアが特定ユーザーのrootlessコンテナとして動いている場合は教えてください（そのユーザーとして実行する仕組みが必要になります）。

## Q3. 1台のノードでPodmanとDockerが両方入っている場合
- **暫定方針: 設定`Container:Runtime`（`auto`/`podman`/`docker`）で選択。`auto`はPodman優先。**
- 両方を同時に管理する必要があれば教えてください。
