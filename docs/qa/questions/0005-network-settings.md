# 0005: ホストネットワーク設定変更の範囲と安全策

- ステータス: 未回答
- 起票日: 2026-09-26
- 関連: 基本設計書 2.1節「ネットワーク設定: ホストネットワーク変更」、ADR-013 ③

ネットワークは**参照（インターフェース・アドレス・経路・DNSの表示）まで実装済み**です。設定変更は、誤るとそのノードに二度と接続できなくなる（リモートから復旧できない）操作のため、実装前に範囲と安全策を確認させてください。**回答をいただくまでは設定変更は実装せず、先に④マルチノード通信に進みます。**

## Q1. 変更できる項目
どこまで必要ですか？（複数可）
- **(a) IPv4アドレス（静的/DHCPの切替、アドレス・プレフィックス）** ← 最低限これは必要と想定
- **(b) デフォルトゲートウェイ**
- **(c) DNSサーバー・検索ドメイン**
- (d) IPv6
- (e) MTU
- (f) ボンディング・VLAN・ブリッジの作成/削除
- (g) 静的経路の追加/削除
- **提案: 初期リリースは (a)(b)(c)。(d)〜(g)は必要になったら追加。**

## Q2. 対応するネットワーク管理方式
OSによって設定の仕組みが違います。
| 方式 | 主な対象 |
|---|---|
| NetworkManager（nmcli） | RHEL 8/9、AlmaLinux/Rocky、Ubuntu Desktop |
| netplan | Ubuntu Server 18.04以降 |
| ifupdown（/etc/network/interfaces） | Debian |
| network-scripts（ifcfg-*） | RHEL 7 / CentOS 7（EOL） |

- 実際の運用環境で使われている方式はどれですか？
- **提案: まずNetworkManager（RHEL系が主と想定）。他は優先度を教えていただければ順次テンプレートを追加。**

## Q3. 接続が切れた場合の安全策
**提案: 「確認付き適用（自動ロールバック）」方式**
1. 変更を適用する前に現在の設定を保存する。
2. 適用後、**一定時間内（例: 120秒）に利用者が「確定」を押さなければ自動で元の設定に戻す**（`netplan try`や、ルーター機器の「確認しなければ元に戻す」と同じ考え方）。
3. 新しいIPで接続し直せた場合はそこで「確定」を押す。
4. 戻す処理はSystemAgent内のタイマーで行うため、API経由の接続が切れても実行される。

- この方式でよいですか？ 確認までの時間の希望はありますか？
- 加えて「SystemAgent自身が通信に使っているインターフェースの変更は警告を出す」ようにします。

## Q4. 検証方法
WSLのディストリビューションは全てネットワークを共有しているため、WSL上で実際のIPを変えると検証環境全体（MariaDB含む）が切れます。
- **提案: ダミーインターフェース（`ip link add ... type dummy`）をNetworkManagerの管理下に置き、それに対して変更・ロールバックを検証する。** 実NICでの確認は実機で別途お願いする形になります。
- 検証用のVM等（Hyper-V）を用意できる場合は教えてください。
